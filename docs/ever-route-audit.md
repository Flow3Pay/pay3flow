# Аудит покрытия криптообменов, 18 октября 2026

## Вывод

**Полного покрытия сейчас нет.** Особенно слабо покрыта покупка нативного
EVER в Everscale. Во всех 18 проверках этого назначения единственным
результатом был расчёт по спотовым тикерам Gate. Он не проверяет возможность
ввода/вывода по выбранной сети и не является подтверждённым предложением
доставить EVER в кошелёк.

Для Ethereum ситуация иная: есть отдельные котировки CoW и Symbiosis на
ERC-20 представление EVER. Его нельзя считать выплатой нативного EVER в
Everscale. Для OTC эти две формы ликвидности необходимо учитывать отдельно.

## Метод и воспроизводимость

Проверен публичный production API `https://pay3flow.lefine.pro`:
9 исходных активов × 2 сети назначения EVER × 2 размера обмена = 36 запросов;
ещё 18 запросов проверяют 9 контрольных направлений без EVER. Все запросы
разрешают разные площадки и запрашивают до 100 отображаемых маршрутов.
`routes_found` учитывает результаты до этого ограничения.

Это выборочная проверка 54 запросов, а не декартово произведение всего рынка.
Суммы указаны в исходном активе. Ордера, подписи и переводы не создавались.
Ответы очищены от подписанных execution-токенов.

- [Ответы API и статусы провайдеров](audits/crypto-coverage-2026-10-18.json).
- [Скрипт повторной проверки](../scripts/audit_crypto_routes.py).

```sh
python3 scripts/audit_crypto_routes.py \
  --base-url https://pay3flow.lefine.pro \
  --output /tmp/crypto-coverage.json
```

Скрипт использует две параллельные HTTP-проверки; провайдеры могут ограничивать
частоту запросов. Результаты зависят от времени, суммы, сети и учётных данных
серверной установки. Состояние production зафиксировано до изменений этого
аудита; повторный запрос к production не проверяет локальные исправления.

## Что именно происходит с CoW и EVER

В скачанном стандартном списке CoW было 281 токен; EVER в нём отсутствовал.
Каталог Symbiosis содержал Ethereum-токен:

- адрес `0x1ffEFD8036409Cb6d652bd610DE465933b226917`;
- символ каталога `EVER`, точность **9**, не 18;
- сам интерфейс CoW показывает **Wrapped EVER / WEVER**, **Unknown Source**
  и запрос **Import token**.

Это объясняет, почему пользователь не находит EVER обычным поиском в CoW.
[Прямая ссылка CoW на USDC → этот контракт](https://swap.cow.fi/#/1/swap/0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48/0x1ffEFD8036409Cb6d652bd610DE465933b226917)
открывает импорт, а не подтверждает сделку. Во время отдельной проверки API CoW
вернул HTTP 200 и положительный `buyAmount` на 100 USDC. Это котировка,
не доказательство исполнения, глубины или возможности получить нативный EVER.
После импорта браузерная проверка не установила полный исполнимый сценарий;
подключение кошелька и подписание не выполнялись.

## Обнаруженные причины и локальные исправления

1. Обычный crypto→crypto поиск проверял прямую пару у каждого провайдера.
   Составление двух независимых котировок существовало только для циклов.
   Добавлен ограниченный поиск `источник → общий актив@сеть → назначение`
   между разными выбранными провайдерами при `allow_cross_venue=true`.
   Второй шаг получает реальный quoted output первого. Выход USDC/Base
   не соединяется с входом USDC/Ethereum. Шаги и их суммы передаются в
   существующем `cycle_legs` также для маршрутов `crypto_to_crypto`.
2. Узкий общий список CoW использовался и для метаданных 0x/Barter.
   Дополнительный каталог Symbiosis теперь расширяет адреса и точность
   ERC-20, с приоритетом основного списка CoW. Нативные активы не принимаются
   за ERC-20 из-за пустого адреса. Наличие метаданных лишь разрешает запрос:
   результат требует успешной котировки, а не только наличия токена в списке.
   Неоднозначные группы тикер/сеть/контракт исключаются из общего DEX-каталога.
   При обновлении каждый каталог заменяет свой предыдущий снимок, чтобы
   удалённая или ставшая неоднозначной запись не оставалась в нём навсегда.
3. Фоновый коэффициент мог заменять живой список котировок одним расчётом,
   теряя предложения обменников, ограничения суммы и комиссии. Для обычного
   crypto→crypto поиска этот обход удалён: используются свежие `quotes`.
4. BestChange брал только первую единицу каталога для токена и сети.
   Теперь проверяются комбинации совпадающих единиц в существующем бюджете;
   добавлены отсутствующие нативные сопоставления EVER/Everscale и ZEC/Zcash.
   Это не означает, что каталог BestChange фактически предлагает EVER.
5. Ошибки обычных quote-запросов ранее могли остаться только в логах.
   Теперь их статусы поступают в progressive response. Ограниченный поиск
   crypto→crypto публикует `routes_exhaustive=false`. Отсутствующие записи
   частичного capability snapshot догружаются, а не исключают провайдера.
6. Код долларовой оценки в конвертере сохранился с коммитов `e51b31d` и
   `a6cd4eb`; EVER отсутствовал в backend-карте цен. Добавлены EVER/Everscale
   и 10SET/Tenset. Backend и frontend повторяют неудавшуюся первоначальную
   загрузку через минуту; успешные цены по-прежнему обновляются раз в час.
   Устаревшая/отсутствующая цена не заменяется выдуманным курсом.

Новый составной поиск ограничен 8 промежуточными кандидатами на входного
провайдера, 32 запланированными запросами на провайдера в этой фазе,
8 входными предложениями на кандидат и общим 60-секундным workflow-бюджетом.
Каждая внешняя котировка ограничена 12 секундами; запросы одного провайдера
идут по существующей paced lane с обработкой rate limits. Прямые котировки
публикуются до составной фазы. Лимит отображения не ограничивает discovery.
Это расширение покрытия, а не доказательство исчерпывающего поиска.

Дополнительная read-only проверка вне исходной матрицы получила две
последовательные котировки: NEAR Intents `0.02 BTC → 1629.515056 USDC Ethereum`,
затем CoW на ровно `1629515056` атомарных единиц USDC →
`233689.083110962` Wrapped EVER. Это пример отсутствовавшего класса составных
путей. [Оба ответа и точный стык сумм](audits/btc-usdc-ever-two-quotes-2026-10-18.json)
сохранены отдельно. Размер 0.02 BTC превышает размеры BTC в исходной матрице;
он не доказывает доступность меньших сумм. Ни одна из котировок не исполнялась.

## Что остаётся непокрытым

- **Нативная ликвидность Everscale:** нет адаптеров Octus Bridge / FlatQube /
  BuyEver. [Документация Octus о получении EVER](https://docs.octusbridge.io/use/getting-started/how-to-get-ever)
  описывает эти пути; [FlatQube](https://docs.flatqube.io/) — DEX Everscale.
  Их текущие резервы, точные котировки, доступность мостов и превращение
  wrapped EVER в native EVER в этом аудите не подтверждены. Страницы
  документации не являются основанием рисовать новые маршруты.
- **CEX вывод:** Gate даёт цену, но интеграция не подтверждает статус,
  сеть, минимум и комиссию ввода/вывода EVER. Для OTC нужен отдельный учёт
  доступного объёма и состояния депозитов/выводов.
- **Сбои существующих источников:** Cifra вернула невалидный JSON с HTTP 200
  во всех 54 проверках; 0x вернул HTTP 403 в четырёх; Symbiosis отклонял часть
  котировок с `Price impact is too high`; CoW bridge не поддерживал EVER как
  конечный токен NEAR-моста. Увеличение display limit этого не исправляет.
- **Глубина:** тикеры CEX не заменяют order book; большие суммы могут менять
  цену DEX. Тест двух размеров не доказывает размер ликвидности.
- Нет произвольного обхода всех активов и цепочек любой длины. Не добавлены
  другие неинтегрированные биржи или агрегаторы без проверки их API.
- Общая модель стыкует `symbol@network`, не адреса контрактов между всеми
  источниками. Разные обёртки с одинаковым тикером требуют дополнительной
  проверки идентичности и возможности перевода; составной результат остаётся
  оценкой последовательных шагов, а не гарантией доставки.
- Долларовая цена привязана к идентичности underlying asset по явному ID.
  Она не обещает выкуп конкретной обёртки по тому же курсу. Низколиквидные
  активы, включая 10SET, могут не пройти проверку свежести у источника цен.

## Проверка изменений

Регрессионные проверки покрывают составление BTC → USDC → EVER,
передачу точного quoted output во второй шаг, отключённые cross-venue routes,
фильтр выбранных провайдеров, несовпадающие сети промежуточного USDC,
добавление EVER с 9 decimals и приоритет основного каталога.
Браузерные проверки покрывают EVER в Everscale, сохранение выбора после
перезагрузки и восстановление USD-оценки после первой ошибки API.

Проверки: `cargo test --all-features` — 337 тестов библиотеки и 32 теста
Providerfile прошли, 38 явно помеченных ignored-проверок не запускались;
`cargo clippy --all-targets --all-features` завершился с существующими
предупреждениями репозитория. `cargo fmt --check`, проверка генерируемого SQL,
`npm run check`, `npm run build`, 61 frontend unit test и 4 выбранных
Playwright-теста прошли. Новые Rust-проверки дополнительно наблюдались
падающими при временной инверсии ключевых утверждений; утверждения восстановлены.

Изменения находятся в рабочей копии. Этот документ не утверждает, что они
развёрнуты в production или что после них измерен рост реальной ликвидности.
