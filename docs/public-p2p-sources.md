# Public P2P source policy

Pay3Flow подключает Binance, Bybit, OKX и Bitget как read-only источники
объявлений через JSON-конфиги в `backend/providers/`. В `docker-compose.yml`
они включены по умолчанию, а конкретный источник можно отключить через
`P2P_<SLUG>_ENABLED=false`.

Поиск остаётся read-only: Pay3Flow не создаёт ордера, не авторизуется в
сторонних сервисах и не принимает реквизиты полной банковской карты.

## Кандидаты

| Источник | Что реально даёт | Регистрация/API | Решение |
|---|---|---|---|
| Rapira P2P | Публичная web-страница P2P | Публичный API не подтверждён; страница динамическая | JSON-конфиг после проверки официального API и формата данных |
| CoinGecko | Агрегированные цены и market data | API-планы и лимиты меняются; это не P2P-объявления | Только reference price, не источник P2P routes |
| BestChange | Курсы и резервы обменников | Официальный API требует API key | Подключать только через легальный API key |
| Exnode | Обменные/merchant API | API требует public/private keys и подпись | Не использовать без зарегистрированного API-доступа |

Для источника с совместимым JSON API отдельный Rust-адаптер не нужен: достаточно
добавить ссылку в `backend/providers/reg.json` и описать request/response mapping
по правилам из [`docs/p2p-search.md`](p2p-search.md). Если API использует
нестандартную подпись, пагинацию или требует сложную бизнес-логику, его нельзя
подключать только декларативным конфигом без отдельного решения по безопасности.

Нельзя выдавать эти источники за проверенных solver'ов. До появления легальных
public/read-only интерфейсов они показываются только как исследуемые источники,
а не как исполнители расчётов.

Модалка поиска принимает только параметры фильтрации. Полный номер карты, CVV,
пароли и коды подтверждения в Pay3Flow вводить нельзя.
