# Multisig port contract

Source: somefriday/evernode_cli at 8ce3535 (Python wallet validation and the
vendored Ever-Validator Msig-prep.sh, Msig_deploy.sh, transfer_amount.sh and
Sign_Trans.sh). The new deliverable is a standalone Rust binary, evernode-rs,
with no Python binding or script fallback. Validator hosting and DePool
operations remain in the original CLI and are outside this wallet port.

## Boundary and invariants

The units of parity are quorum acceptance, imported custodian verification,
key derivation, and the ABI method/parameter objects crossing the TVM backend
process boundary. Wallet logic runs in Rust; ever-cli (or compatible tonos-cli)
remains responsible for TVM address derivation, ABI encoding, message signing,
account queries and broadcasting, as in the source. Rust generates 12-word
English BIP39 phrases and derives the BIP32 secp256k1 secret at
m/44'/396'/0'/0/0, then uses that secret as the Ed25519 signing seed, matching
ever-cli's crypto.rs. No custom cryptographic primitives are implemented.

Preserve 1..31 distinct owners, 1..owner-count required signatures, owner order
for deployment, first-owner deployment key, uint256 decimal/hex on-chain
public keys, order-independent set comparison for recovery, raw addresses,
submitTransaction (allBalance=false) and confirmTransaction(transactionId).
Never round token amounts through floating point. Never substitute a newly
generated address for the expected address of an imported multisig.

JSON object ordering, error wording, absolute directories and CLI flag layout
may differ. They are not used as parity criteria. File names for address,
custodian keypairs and MSKeys_<name> seed backups follow the source convention.

## Adapter choices

This is a multisig-only standalone interface: wallets do not require a node,
root privileges, a DePool address or validator setup stages. Existing Python
entry points are not routed into Rust; invoke evernode-rs explicitly. New
wallet manifests are stored in separate directories and do not alter node
metadata. Recovery verifies before publishing usable wallet state. It can
fail while leaving a private directory for diagnosis; existing data is never
overwritten. Explicit custodian selection replaces the original automatic
bulk signing assumption; each confirmation checks the actual on-chain index
and confirmations mask. Deployment refuses active/unfunded accounts and
checks its computed address. Broadcasts happen only with --yes. Encoding without broadcast is available without --yes; deployment and
transaction commands still query the chain to validate their inputs.

## Evidence

- The frozen 1,226-case corpus was generated by running upstream Python
  validation/comparison code. Rust checks those recorded quorum and key-set
  results, including failures, without requiring the Python application.
- Golden key vectors come from upstream ever-cli tests/mnemonic.rs,
  tests/test_cli.rs and tests/samples/exp.json, plus its documented vector.
- Offline fake-backend CLI integration tests cover file permissions, imported
  address preservation, malformed responses, failed recovery, duplicate
  owners, deployment guards, numeric boundaries, explicit confirmation,
  backend failure/timeout, and no broadcast without --yes.
- Embedded ABI/TVC assets are copied unchanged from the vendored contracts;
  tests check their pinned SHA-256 byte digests.

These checks establish local behavior and command construction. They do not
claim live-chain deployment, validator operation or equivalence of every
behavior in the original scripts. Network integration requires an installed
compatible backend and a funded test wallet; it is not run automatically.

## OTC feature extension

The `otc` subcommands add independent-key buyer/seller/arbitrator operation
with a fixed 2-of-3 Safe quorum. This is a feature extension, separate from
the behavior-preserving port of the general `wallet` commands. It reuses
the backend and pinned contract assets while adding reviewed trade hashes,
public-only setup/import, exact release/refund checks, network/code identity
checks and receipt-based broadcast reconciliation. See [OTC.md](OTC.md) for
the interface and its distinction from an on-chain escrow or atomic swap.
